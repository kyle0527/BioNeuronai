## 第一部分：願景（用你的話整理）

把你在整段討論中表達的核心想法整理成一句話：

> **不要建一個「知道很多事情」的 AI，而是建一個「知道怎麼搞懂事情」、會在交易中不斷自我學習、自我成長、自我擴充的系統。**

具體拆解你的要求：

1. **交易即訓練** — 不要獨立的訓練期，讓系統在虛擬 API 裡持續交易，這個過程本身就是學習
2. **保存一切** — 「有發生過的事就有可能再發生」，每個決策時刻的完整世界狀態都要存
3. **類人性格** — AI 要有你那種「不搞懂不罷休、主動追問、不接受模糊答案」的特質
4. **內外搜索** — 對內能查自己的記憶（RAG），對外能查網路
5. **不暴增容量** — 本地資源不能遠大於現況
6. **務實獲利** — 最終要真的賺錢，不是架構漂亮
7. **不重造輪子、無包袱** — 現成的直接用，沒有東西非保留不可

## 第二部分：誠實的現實（你必須知道的硬限制）

整合建議之前，先把三個無法迴避的真相講清楚：

### 真相一：100M 的 TinyLLM 撐不起「類人性格」

「主動追問、知道自己不知道什麼、好奇心驅動」這種能力，**是大型模型才有的特性，不是訓練資料的問題，是參數規模的硬限制**。再多的對話語料也無法讓 100M 模型擁有真正的推理性格。

→ **結論：性格層必須由大型模型提供。**

### 真相二：「湧現」要分清楚是哪一種

| 成長類型 | 100M 模型能達成嗎 | 說明 |
|---------|------------------|------|
| 信號預測能力提升 | ✅ 能 | 線上學習真的有效，這是真實的成長 |
| 中文交易知識增加 | ✅ 能（有限） | LoRA 微調可以補 |
| 推理能力的湧現 | ❌ 不能 | 這需要大模型規模 |
| 主動好奇、自我提問 | ❌ 不能 | 同上 |

→ **結論：TinyLLM 的「自我成長」是真的，但成長在「信號預測」，不是「推理性格」。**

### 真相三：獲利無法被架構保證

你已經正確指出——這種系統不該用傳統回測驗證（功能都還沒齊，且 LLM 決策非確定性）。真正的驗證是**長期 paper-live**。但要誠實：再好的架構也不保證賺錢，paper-live 跑出來才算數。

## 第三部分：核心架構決策（我的建議）

整段討論最關鍵的一個決定：**TinyLLM 全包，還是分工？**

### 建議採用：分工架構（混合）

理由：它同時滿足你「類人性格」+「自我成長」+「不暴增容量」三個看似衝突的要求。

```
你想要的「機車、追根究柢的性格」
   → 其實就是你現在跟 Claude 對話的這種互動本身
   → 它已經存在，不需要重新訓練塞進小模型
   → 把它接進系統當「大腦層」即可（雲端 API，本地零負擔）

你想要的「自我成長」
   → 由 TinyLLM 在交易中線上學習達成（信號層真實進化）
   → 由系統的記憶/語料持續擴充達成（系統知識成長）
```

**這不是放棄 TinyLLM 的成長，而是讓每一層做它最擅長的成長。**

## 第五部分：自我學習系統（核心機制）

這是整個系統的心臟，由四個迴圈組成：

### 迴圈一：信號層線上學習（TinyLLM 自我成長）

```
進場：存 Action Record（特徵1024 + logits512 + 完整市場背景）
   ↓
持倉 → 出場：計算 reward（淨PnL × 時間懲罰 × 槓桿懲罰）
   ↓
寫入 Replay Buffer（記憶體環形緩衝 + Parquet 冷儲存）
   ↓
每 N 筆 → 優先抽樣 batch（罕見/大虧損事件權重高）
   ↓
LoRA 增量更新（凍結主體，只更新適應層，學習率 1e-5）
   ↓
TinyLLM 信號預測能力進化
```

> 接現有 `src/nlp/lora.py`（已存在但從未接進交易迴圈）

### 迴圈二：記憶擴充（系統知識成長）

```
每筆交易的中文描述（自動生成）→ 對話知識庫
你和各 AI 的對話（提取後）→ 對話知識庫
特殊市場事件 → 事件記憶
   ↓
全部進 FAISS 向量索引
   ↓
大腦層遇到相似情況時可檢索：「過去類似狀況我怎麼處理的？」
```

### 迴圈三：知識缺口驅動（你要的「好奇心」機制）

```
系統遇到信心很低的情況（confidence < 0.5）
   ↓
不只是跳過，而是記錄「知識缺口」：
   {情境, 我不確定什麼, 想搞懂的問題}
   ↓
大腦層生成具體問題 → 透過外部搜索 / 與你對話來解答
   ↓
答案進入語料 → 下次遇到類似情況就懂了
   ↓
這就是「自我擴充」的具體實現
```

### 迴圈四：策略基因演化（已有，繼續跑）

```
現有 self_improvement.py 的基因演算法
   ↓
每日自動觸發（目前需手動，要改成排程）
   ↓
進化策略參數層面（RSI週期、均線、止損倍數）
```

→ 迴圈一進化「神經網路」，迴圈四進化「策略參數」，互補不衝突。

## 第六部分：資料儲存設計

### 動作記錄（Action Record）— 三個時刻觸發

```
觸發：產生信號時 / 進場時 / 出場時

內容：
  時間維度    timestamp, symbol, action_type
  模型思考    features(1024), logits(512), signal_type, confidence
  策略意見    5策略各自方向+信心, 融合權重, 共識強度
  市場背景    price, regime, funding_rate, OI, 清算風險,
              訂單簿失衡, 新聞事件分數
  帳戶狀態    balance, drawdown, 持倉數
  出場補充    淨PnL, 持倉時長, 出場原因, 最大順勢/逆勢幅度
```

### 分層儲存

| 層級 | 儲存方式 | 用途 | 大小估計 |
|------|---------|------|---------|
| 熱資料 | 記憶體 Replay Buffer（最近2000筆） | 即時訓練 | ~16MB |
| 冷資料 | Parquet（按月分割） | 批次訓練/查詢 | ~29MB/年 |
| 元資料 | 現有 SQLite（擴充欄位） | 索引/查詢 | 小 |
| 向量 | FAISS | RAG 檢索 | 中 |

### 資料量現實（回答你的疑問）

你擔心資料太少——這個擔心對「從頭訓練 LLM」是對的（需要 100GB+），但對我們的場景是足夠的：

| 目的 | 需要量 | 我們的來源 |
|------|--------|-----------|
| 從頭訓練 LLM | 100-200GB | ❌ 不做這件事 |
| LoRA 微調信號層 | 幾千筆 | ✅ 交易記錄夠 |
| LoRA 微調中文知識 | 幾千-幾萬筆 | ✅ AI對話語料夠 |
| 性格 | 不靠訓練 | ✅ 大腦層 + 對話 few-shot |

## 第七部分：自然語言 / 性格訓練（你的新重點）

### 資料來源：你和各 AI 的對話

你的對話方式本身就是高品質訓練信號——它記錄了「一個追根究柢的人逼出 AI 深度回答」的完整過程。

### 提取要保留「行為模式」而非只是「知識」

```
不只存最終答案，要存「追問的過程」：
  你：為什麼會這樣？
  AI：因為 X
  你：但 X 什麼時候不成立？
  AI：當 Y 時...
  
→ 訓練模型學會「問題背後還有問題」這種思維
```

### 提取流程

```
各 AI 對話匯出（JSON）
   ↓ parser（按平台格式）
內容過濾（中文比例 / 交易主題 / 去敏感資訊 / 去寒暄）
   ↓
格式轉換（instruction / conversation 格式）
   ↓
去重（相似度 > 0.85 只留一筆）
   ↓
data/text_corpus/ → 用於大腦層 few-shot + TinyLLM LoRA
```

### 性格如何落地

```
主要：大腦層的系統提示明確定義性格
  「遇到不確定就說出來，不猜測當答案」
  「每個解釋連結到更基礎的原理」
  「對『通常』追問邊界條件」
  「發現知識缺口就記錄並尋求補充」
   + 你的對話語料當 few-shot 範例

次要：TinyLLM 用對話語料做 LoRA（補中文交易表達）
```

## 第九部分：分階段路線圖

> 順序原則（依你的指正）：先建功能 → 再 paper-live 驗證，不是先回測。

| 階段 | 產出 | 為什麼是這個順序 |
|------|------|----------------|
| **P0 動作記錄層** | Action Record 存儲（信號/進場/出場三時刻） | 所有學習的基礎，沒這個後面都做不了 |
| **P1 出場閉環** | 動態出場管理 + OCO 組合單 | 出場乾淨，reward 信號才不是雜訊 |
| **P2 對話語料管道** | 提取工具 + 語料庫結構 | 可與 P0/P1 並行，低成本持續累積 |
| **P3 記憶層擴充** | RAG 擴充（交易史/知識/對話）+ 外部搜索工具 | 大腦層需要能查內外資料 |
| **P4 大腦層** | 大模型推理層 + 性格 + 搜索調度 + 硬風控守門 | 接上「類人」決策核心 |
| **P5 線上學習** | Replay Buffer + LoRA 更新 + reward 函數 | TinyLLM 開始自我成長 |
| **P6 自我擴充** | 知識缺口記錄器 + 自我提問迴圈 | 「好奇心」機制閉環 |
| **P7 paper-live 長跑** | 端到端持續運行驗證 | 真正的獲利驗證關卡 |

**第一步建議：P0 動作記錄層**，因為它是所有自我學習的地基。

## 第十部分：風險與提醒

- **災難性遺忘**：線上學習若學習率太大，幾筆大虧損會洗掉所有舊知識 → 用 LoRA + 小學習率 + Replay 控制
- **雜訊學習**：出場若沒邏輯，reward 就是雜訊 → P1 出場閉環必須先做
- **大腦層成本**：低頻決策 + 分層模型，每月數十美元等級
- **大腦層幻覺**：硬風控守門是最後保險絲，唯一能下單者
- **獲利不保證**：paper-live 長跑才是真相，不是架構
- 不構成投資建議；先測試網/Demo，通過才考慮主網
