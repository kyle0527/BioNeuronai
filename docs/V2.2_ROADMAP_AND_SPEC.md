# BioNeuronAI v2.2 發展藍圖與技術規格 (Roadmap & Spec)

> 更新日期：2026-05-02
> 目的：確立 v2.1 穩定版之後的下一步核心開發目標，聚焦於分析模組重構、事件合約驗證，以及 RAG 系統與策略融合的最終對接。

## 🎯 核心目標：從靜態演算法邁向動態情境感知

目前 v2.1 已經完成了「動態演算法融合（Algorithmic Fusion）」的基礎建設，所有策略都能在沒有深度學習模型直接介入的情況下，依靠啟發式權重穩定運作。

**v2.2 的核心目標是讓系統具備「情境感知（Context-Awareness）」**，特別是針對突發新聞與市場事件，能夠精準計算事件的持續時間與影響力，並由神經網路動態決定策略資金分配權重。

---

## 🏗️ Phase 1: 分析模組重構與事件合約 (Event Contract)

這是目前最核心的待辦技術債（原 T4/T5）。

### 1.1 `news/analyzer.py` 拆分
目前的 `CryptoNewsAnalyzer` 過於龐大（混合了抓取、過濾、情緒分析）。
*   **目標**：將其拆分為 `NewsFetcher` (資料獲取，移至 `data/` 層)、`NewsProcessor` (去重與正規化)、`SentimentEngine` (情緒計算與關鍵字比對)。
*   **效益**：提升可測試性，並符合 `data/` 負責外部 API 的架構原則。

### 1.2 事件合約驗證框架 (NewsEventContract)
目前的情緒分數缺乏「時間維度」，導致利多新聞的影響力可能被無限期延長。
*   **目標**：實作 `NewsEventContract`。
*   **規格**：
    *   每個重大新聞生成一個 Contract，包含：`event_type`, `urgency`, `initial_impact`, `decay_rate`, `expires_at`。
    *   **自適應衰減**：新聞影響力隨時間呈指數或線性衰減。
    *   **驗證閉環**：在事件到期後，系統自動回顧該新聞期間的真實價格變化（PnL），將結果標註為高品質的訓練資料（供未來模型使用）。

## 🧠 Phase 2: RAG 知識庫對接策略融合

目前的 RAG 系統已能將盤後日報與新聞存入 FAISS 向量資料庫，並在 `pretrade` 階段進行風險提示，但尚未與即時策略權重掛鉤。

### 2.1 充實 `EventContext`
*   **目標**：在 `TradingPlanController` 呼叫策略前，主動向 `InternalKnowledgeBase` 查詢當前交易對與市場狀態的歷史相似事件。
*   **實作**：將檢索到的歷史勝率與交易規則，封裝進 `EventContext` 中。

### 2.2 策略融合權重調整
*   **目標**：`AIStrategyFusion` 接收到包含 RAG 檢索結果的 `EventContext` 後，動態調整子策略權重。
*   **情境範例**：若 RAG 檢索發現「過去 3 次類似的 BTC 突破事件都遭遇假突破」，則融合引擎自動調降 `BreakoutStrategy` 的權重。

### 3.2 模型架構規格

- **輸入 (68 維)**：市場特徵 60 維 + 事件特徵 8 維
- **隱藏層**：128 → 64（LayerNorm + ReLU + Dropout）
- **輸出**：5 個策略的 Softmax 權重（總和 = 1.0）
- **參數量**：17,797 個
- **訓練資料**：34,141 根 BTCUSDT 1H K 線（2020-2023）
- **訓練樣本**：3,406 個；最佳驗證損失：0.5358（KL 散度）

### 3.3 啟用方式

```python
from bioneuronai.strategies.strategy_fusion import AIStrategyFusion, FusionMethod

fusion = AIStrategyFusion(fusion_method=FusionMethod.META_LEARNER)
```

### 3.4 重新訓練

```bash

```

### 3.5 後續改進方向

2. **事件特徵補全**：待新聞管線穩定後，將 `CryptoNewsAnalyzer` 的情緒分數即時傳入
3. **定期重訓**：隨市場環境改變，建議每季度重新訓練一次

## 📌 執行優先順序與雲端訓練計畫（更新後：2026-05-05）

### ✅ 階段性里程碑：E2E 基礎架構與風控驗證完成
經過一系列的測試（包含 UI 介面控制、Testnet 模擬下單、Backtest 歷史回測驗證），目前 v2.2 系統的核心交易引擎與風控邏輯（包含 1% 止損防守與成本驗證）已證實具備極高穩定性。在基礎策略未優化的狀態下，最大回撤仍能控制在極低水準（7.66%）。系統基礎建設已完全就緒。

### 🚀 下一步：雲端部署與大模型持續訓練 (Cloud AI Training)
目前的基礎策略（如均值回歸）在單邊趨勢盤中會產生負報酬，必須依賴 AI 模型的介入與進化。
因此，下一個核心任務是將系統轉移至雲端（GCP/AWS）進行大規模運算：
1. **策略演化 (`evolve`)**：在雲端利用 `python main.py evolve` 基因演算法進行跨週期、跨幣種的暴力參數尋優。
2. **Meta-Learner 雲端重訓**：運用雲端 GPU 資源，餵入真實標籤資料與 `NewsEventContract` 特徵，訓練出能適應不同市場微觀環境（Market Regime）的最佳策略權重神經網路。
3. **大模型 (100M Model) 部署**：完成訓練後，將 `my_100m_model.pth` 掛載回正式交易引擎中。
