## 0. 三條鐵律（本計畫的前提）

1. **沒有包袱** — 任何現有元件都可砍可換，不為保留而保留。
2. **容量不暴增** — 最終系統的本地資源不得遠大於現況（大腦放雲端 API，本地保持精簡）。
3. **目標只有一個：實際獲利** — 架構漂亮不算數，扣掉手續費/滑點/資金費率後**淨賺**才算數。

附加原則（你指定的）：**不重造輪子。** Commodity 功能一律抓現成的；自製只留給「會產生獲利優勢」的重點。

## 1. 核心設計哲學

```
大腦提案，風控拍板。
（LLM 負責「類人推理/適應」，確定性風控層負責「不爆倉」，兩者分權）
```

- **先有 edge，再談架構**：架構不會憑空生出獲利。先用嚴格回測證明有優勢，才值得投入改架構。
- **大腦在雲端**：類人推理來自外部大型推理模型 API，本地只跑輕量編排 → 容量不暴增。
- **小模型降級成工具**：現有 111M TinyLLM 不丟，但從「決策者」降為「眾多輸入信號之一」。

## 2. 買 vs 自建 決策表（本計畫核心）

> 原則：**綠色=直接抓現成的，別花時間；紅色=自製,把腦力全押這裡。**

| 元件 | 決策 | 用什麼 | 理由 |
|------|------|--------|------|
| Multi-agent 編排框架 | 🟢 **買** | LangGraph（業界標準；TradingAgents 也是用它） | 編排/狀態機/checkpoint 是 solved problem，自製浪費時間 |
| Agent 角色拓撲（分析師/多空/交易員/風控） | 🟢 **借** | 參考 TradingAgents 的成熟拓撲，改造成加密合約版 | 別重新發明開會流程，借成熟設計再客製 |
| 推理大腦（LLM） | 🟢 **買** | Claude / GPT API（分層：便宜模型做摘要、強模型做決策） | 自訓大模型 = 容量暴增且達不到推理能力 |
| 交易所連線 | 🟢 **買（評估替換）** | `ccxt`（統一多所、內建簽名/限流/重連） | 現有手刻 `binance_futures.py` 維護成本高；ccxt 久經實戰 |
| 技術指標 | 🟢 **買（已在用）** | TA-Lib | 保留，標準庫 |
| 向量檢索 / RAG | 🟢 **買（已在用）** | FAISS | 保留 |
| 新聞 / 情緒資料 | 🟢 **買** | CoinDesk RSS + Google News RSS 正式入口 | 不自建爬蟲農場，也不增加第三、第四新聞來源 |
| 資料儲存 | 🟢 **買（簡化）** | SQLite / DuckDB / Parquet | 現有 56KB 自製 `database_manager.py` 疑似過度設計，砍成標準方案 |
| K 線 / 行情快取 | 🟢 **買** | ccxt + Parquet 落地 | 標準做法 |
| 部署 / 排程 | 🟢 **買** | Docker（已有）+ 系統 cron / APScheduler | 保留 |
| **幣安期貨 MCP 工具層** | 🟢 **買（直接用）** | `mcp-binance-futures`（Muvon 開源） | 幣安官方生態認可的 MCP server，已實作全套期貨工具，不用手刻 |
| **交易優勢（edge）/ 信號假設** | 🔴 **自建** | 你的核心 IP | **這是唯一真正差異化的東西，腦力全押這裡** |
| **加密合約版推理 prompt + 多空辯論** | 🔴 **自建** | 客製 prompt 工程 | 通用框架沒有加密合約（資金費率/槓桿/清算）的 know-how |
| **硬風控守門層** | 🔴 **自建** | 確定性 Python，不可被 LLM 繞過 | 防 LLM 幻覺爆倉，必須自己掌控、可審計 |
| **成本真實的驗證關卡** | 🔴 **半自建** | walk-forward + 資金費率感知成本模型 | 加密合約成本結構特殊（8h 資金費率/taker 費/depth 滑點），保留你的 `trading_costs.py` 並補強 |
| **記憶 / 反省迴圈內容** | 🔴 **自建** | 決定「該記住什麼教訓」 | 框架給容器，但「學什麼」是你的 edge |
| **SKILL.md 技能定義** | 🔴 **自建（輕量）** | 幣安 Skills Hub 格式 | 定義 BioNeuronAI 能力邊界，讓任何 agent 框架都能理解和調用 |

**一句話**：除了「edge、加密版推理、硬風控、驗證關卡、SKILL.md」這五項自製,其餘全部抓現成。

## 3. 幣安 AI Agent Skills 研究報告（2026-06-03）

> 研究結論：幣安已把「LLM 直接操盤」這件事官方化，且完全開源。這對我們意義重大。

### 3.1 幣安在做什麼

**2026年3–5月，幣安分三批推出 24 個 AI Agent Skills：**

| 批次 | 技能類別 | 關鍵能力 |
|------|---------|---------|
| 第一批（7個）| 現貨交易 · 錢包洞察 · 代幣詳情 · 市場排名 · Meme 信號 · 交易信號 · 合約風險審計 | 完整進場流程 |
| 第二批（4個）| 進階市場數據 · Alpha 早期項目 · 智能資金流向 | 信息優勢 |
| 第三批（13個）| 期貨 · 選項 · 槓桿 · 算法下單（TWAP/VWAP）· 倉位管理 | 完整合約操作 |

**核心技術**：
- 協議：**Model Context Protocol (MCP)** — Anthropic 制定的開放標準，Claude Code 原生支援
- 格式：**SKILL.md** — YAML 前端 + Markdown 指令的技能定義檔
- 兼容：LangChain · CrewAI · **LangGraph** · OpenClaw · **Claude Code** — 我們用的框架全在其中

### 3.2 MCP 工具層完整清單（開源實作：`mcp-binance-futures`）

幣安生態中已有開源的 MCP 期貨服務器，暴露以下工具供 LLM 直接呼叫：

```
市場數據（公開，無需認證）
  ping · get_ticker · get_order_book · get_recent_trades
  get_klines · get_symbol_info

帳戶查詢（需 API Key）
  get_balance · get_positions · get_account_summary

訂單管理（需 API Key）
  place_order         → LIMIT / MARKET / STOP / TAKE_PROFIT
  modify_order        → 調整未成交限價單
  cancel_order        → 取消單筆
  cancel_all_orders   → 清空所有掛單
  get_open_orders · get_order_history · get_trade_history

部位與保證金控制（需 API Key）
  set_leverage        → 1–125x 槓桿
  set_margin_type     → ISOLATED / CROSSED
  adjust_isolated_margin → 增減保證金
  set_position_mode   → 單向 / 對沖模式
  get_leverage_brackets → 維持保證金分層
```

**技術棧**：FastMCP + httpx + HMAC 簽名 → 與我們現有 `binance_futures.py` 一模一樣的底層，但已封裝好了。

### 3.3 從幣安做法中借鑑的 5 個關鍵設計

| # | 幣安的做法 | 我們要借鑑的 | 現有系統的現況 |
|---|-----------|------------|--------------|
| 1 | **MCP 協議包裝 API** — 讓 LLM 原生呼叫工具 | 把我們的工具全部 MCP 化（直接用 `mcp-binance-futures`，不手刻） | 手刻 `binance_futures.py`，LLM 無法原生呼叫 |
| 2 | **SKILL.md 能力邊界定義** — YAML 聲明工具能做什麼/不能做什麼 | 寫一份 `skills/bioneuronai-trader/SKILL.md` 定義我們的能力邊界 | 無（能力隱藏在 Python 程式碼中） |
| 3 | **allowed-tools 白名單** — YAML 層限制 agent 只能用指定工具 | 硬風控層的工具白名單設計 | 無 |
| 4 | **分層下單類型** — OCO（一撤另消）/ OTOCO（一觸即撤）組合 | 進場同時自動設好止損+止盈的組合單，現在不支援 | 只有獨立止損/止盈，無組合 |
| 5 | **Demo/Testnet 與 Mainnet 同一套 MCP** — 環境變數切換 | 繼承這個設計，Testnet 先驗，主網再上 | 部分支援，但不夠乾淨 |

## 4. 目標架構（v2，整合 MCP）

```
┌─ 🧠 大腦層（雲端 API · 本地零負擔 · 低頻呼叫）─────────────────┐
│   LangGraph 編排的多 agent 流程：                              │
│   分析師群 → 多空研究員辯論 → 交易員決策                       │
│   分層模型：便宜模型跑摘要/快篩，強模型只在「候選交易點」深推  │
│   輸出：方向 / 信心 / 建議倉位 / 理由 / 「不確定就跳過」        │
└──────────────────────────────┬───────────────────────────────┘
                               ↓ 透過 MCP 呼叫工具
┌─ 🔧 MCP 工具層（幣安官方生態，開源，不手刻）──────────────────┐
│  mcp-binance-futures（全套期貨工具，LLM 原生呼叫）             │
│  + 自製工具：技術摘要 · TinyLLM 信號 · 情緒/新聞摘要           │
│  + SKILL.md 定義能力邊界與 allowed-tools 白名單                │
└──────────────────────────────┬───────────────────────────────┘
                               ↓ 必過（硬性攔截）
┌─ 🛡️ 硬風控守門層（本地 · 確定性 · 不可被大腦繞過）───────────┐
│  Kelly 倉位 · 單筆風險上限 · 日內次數 · 回撤熔斷 · 清算安全距  │
│  OCO/OTOCO 組合單（進場即鎖定止損止盈）                        │
│  大腦只能「建議」,這層說不行就是不行                          │
└──────────────────────────────┬───────────────────────────────┘
                               ↓
┌─ 📓 記憶/反省層（本地小檔 · SQLite/Markdown）────────────────┐
│  交易日誌 + 實際盈虧回灌 → 生成「這次學到什麼」→ 進下次 prompt │
└──────────────────────────────────────────────────────────────┘
```

資料流：行情(MCP get_klines) → 技術摘要+TinyLLM 信號+新聞 → 大腦辯論決策 → 硬風控守門 → MCP place_order(OCO) → 記錄 → 反省回灌。

## 4. 大腦層：Agent 分工與辯論（加密合約版）

借 TradingAgents 拓撲，砍掉股票專屬部分，補上加密合約專屬:

| Agent | 職責 | 模型分層 | 呼叫的 MCP 工具 |
|-------|------|---------|----------------|
| 技術分析師 | 讀技術摘要 + TinyLLM 信號,給多空傾向 | 便宜模型 | `get_klines` · `get_ticker` |
| 資金費率/結構分析師 | 讀資金費率、OI、清算熱圖（加密專屬） | 便宜模型 | `get_ticker`(fundingRate) · 自製 OI 工具 |
| 情緒/新聞分析師 | 讀新聞情緒（現有 RAG） | 便宜模型 | 自製新聞工具 |
| 🐂 多方研究員 ⚔️ 🐻 空方研究員 | **結構化辯論 N 輪,互相反駁** | 強模型 | 唯讀（不下單） |
| 交易員 | 綜合辯論 → 方向/倉位/進出場價 | 強模型 | 唯讀（提案，不直接下單） |
| 風控評審 | 壓力測試這筆（建議層,非硬限制） | 便宜模型 | `get_balance` · `get_positions` |

> 注意：**大腦所有 agent 的 MCP 工具權限全部只讀**。寫入（下單/改槓桿）只有通過硬風控守門後，由守門層本身執行 `place_order`。這是防幻覺爆倉的關鍵設計。

**為什麼這樣「不被框架限制」**：遇到訓練資料外的新事件（突發監管、黑天鵝），分析師用語言理解、多空辯論、交易員權衡——這是推理,會泛化,不是死規則。

## 5. 硬風控守門層（自製重點，不可妥協）

確定性 Python,在大腦之後、下單之前,每筆必過;任一不過直接擋下:

- 單筆風險 ≤ 設定%（Kelly 分數倉位）
- 日內交易次數上限
- 帳戶回撤熔斷（碰上限全停）
- 槓桿/清算安全距離檢查
- 成本效益門檻（預期報酬必須 > 來回成本 × 安全係數）
- **LLM 信心過低 → 強制跳過**（寧可不做）
- **通過後以 OCO/OTOCO 組合單下單**（進場同時鎖定止損+止盈，幣安官方支援）

設計理念:大腦再聰明也可能幻覺,這層是最後的確定性保險絲。**它是唯一有 MCP 寫入權限的元件。**

## 6. 成本控制（呼應「容量不暴增」）

- **分層模型**:無交易機會時用便宜模型快篩（~$0.001/次）;只有出現候選 setup 才召開強模型辯論（~$0.05–0.30/次）。
- **低頻決策**:在 1h/4h 級別操作,大腦延遲幾秒無所謂。
- **粗估**:3 標的 × 每日少數候選 setup → **每日約數美元,每月數十美元等級**,相對任何有意義的交易本金都微不足道。
- 本地只多跑 LangGraph 編排（輕量）+ `mcp-binance-futures`（Node.js 輕量進程）→ **本地容量幾乎不變**。

## 7. 獲利關卡與「止損」標準（最重要）

> 沒有任何架構保證獲利。這道關卡才是真相。任一關沒過,**不上真金白銀**。

```
階段 A：成本真實的 walk-forward 回測
   ├ 含 taker 費 + depth 滑點 + 8h 資金費率
   ├ 多段樣本外測試,禁止用未來資料
   └ Kill 標準：淨 Sharpe < 門檻 或 打不贏 buy&hold/資金費率套利 → 停,回去找 edge

階段 B：數週 paper-live（現有 paper-live 模式）
   └ 真實行情 + 虛擬下單,驗證實盤行為與滑點假設

階段 C：極小額實盤
   └ 用能承受全損的最小金額,驗證真實成交/資金費率/心理

階段 D：逐步放大（僅在 A/B/C 都通過後）
```

## 8. 分階段落地路線圖（v2，整合幣安 MCP）

| 階段 | 產出 | 自製 or 抓現成 | 驗收 |
|------|------|---------------|------|
| **P0 驗證地基** | 成本真實的 walk-forward 回測 harness | 🔴 半自製（補強現有回測 + `trading_costs.py`） | 能對現有系統算出「淨利/Sharpe/最大回撤」 |
| **P1 edge 體檢** | 對現有 TinyLLM+策略跑 P0 | 🔴 自製分析 | **誠實判定現在有沒有 edge** |
| **P2 MCP 工具層** | 安裝 `mcp-binance-futures`；把技術摘要/TinyLLM/新聞包成自製 MCP 工具；寫 `SKILL.md` | 🟢 mcp-binance-futures + 🔴 自製工具 | LLM 能透過 MCP 呼叫行情/帳戶/技術摘要 |
| **P3 大腦層雛形** | LangGraph + agent 拓撲 + 多空辯論（全唯讀） | 🟢 LangGraph + 🔴 客製 prompt | 大腦能輸出帶理由的決策，不直接下單 |
| **P4 硬風控守門** | 確定性風控層 + OCO/OTOCO 組合單 | 🔴 自製 | 大腦建議都要過守門；通過則送 OCO 組合單 |
| **P5 記憶/反省** | 交易日誌 + 反省回灌 | 🟢 SQLite + 🔴 反省內容 | 下次決策帶得到上次教訓 |
| **P6 全鏈 paper-live** | 端到端跑數週 | — | 階段 B 通過 |
| **P7 極小額實盤** | 上線最小金額（Testnet → Demo → Mainnet） | — | 階段 C 通過 |

**關鍵順序**:P0/P1 先做。**如果 P1 證明現在沒 edge,先別急著蓋 P3 大腦——先把力氣花在找 edge 上**（這正是「把時間花在重點上」)。

## 9. 風險與現實提醒

- **多數 AI 交易 bot 扣成本後是虧的**;agentic 升級降低「笨死/爆倉」風險,但**不憑空生 edge**。
- **新風險**:LLM 幻覺(靠硬風控守門擋)、反應變慢(靠高時間級別化解)、API 成本拖累(靠分層模型+低頻控制)。
- **加密合約特有殺手**:資金費率長期吃利潤、清算、極端滑點 → 全部要進回測成本模型。
- 本計畫**不構成投資建議**;一切先在測試網/Demo Trading 驗證，通過後才考慮主網。
